Hook. A computer-use agent loop is mostly not "think hard once." It is: encode a fat multimodal prompt (system + tools + history + latest screenshot) → sample a short action → observe → repeat. Wall-clock and cost are dominated by how you treat that prompt across steps: whether you prefill from scratch, whether you reuse a KV cache, and how fast n grows when each screenshot is hundreds–thousands of tokens. If you only optimize the policy head and ignore prefill/decode asymmetry, OSWorld-scale horizons will feel "mysteriously" slow even when the model is "smart enough."

1. Intuition first: why recompute K and V?

Causal self-attention at position i needs keys and values for all positions ≤ i. In training (or a fresh prefill) you compute K and V for every token in parallel. In autoregressive decode you add one new token. Without a cache you would rebuild K,V for the entire prefix on every step — almost all of that work is identical to the previous step. The fix is trivial in concept and consequential in production: write K,V once, read them forever after (appending the new token's K,V each step).

Standard scaled dot-product attention (Vaswani et al., 2017):

Attention(Q, K, V) = softmax( Q K⊤ / √dhead ) V

For one new query row qt ∈ ℝd against cached K,V ∈ ℝn×d:

scores = qt K⊤ / √dhead  ∈ ℝn
out = softmax(scores) V  ∈ ℝd

That is O(n · d) matvec work per head (per layer), not O(n² · d). The quadratic term appears when you have n queries at once (prefill).

2. Prefill vs decode — two different machines

Pope et al. (MLSys 2023, "Efficiently Scaling Transformer Inference") separate inference into:

  • Prefill: all prompt tokens are present → one parallel forward over length n. Attention builds an n×n (causal) score matrix: ~O(n² d) per layer (plus the usual O(n · params) dense matmuls). Output: logits for the first generated token and a full KV cache.
  • Decode: loop of T steps; each step feeds one token, reads the KV cache, appends one new K,V row. Attention per step ~O(n d); after T steps the cache length is n+T and total attention work ~O(T · n · d) (more precisely Σi=0T−1 O((n+i)d)).
Prefill character. Compute-friendly: large matmuls, high arithmetic intensity when n or batch is large. Weight loads amortized over many tokens. FlashAttention (Dao et al., 2022) mainly helps here by cutting HBM traffic for the n×n attentions.
Decode character. Memory-bandwidth bound at small batch: every step reloads weights (and a growing KV cache) to produce one token. MQA/GQA and KV quantization matter most here. Speculative decoding (Leviathan et al., 2023) attacks the sequential token loop, not prefill.
Rough attention FLOPs (one layer, one head, ignore constants):
Prefill ≈ c · n² · dhead
Decode (T steps, cache starts at n) ≈ c · Σi=0T−1 (n+i) · dhead ≈ c · (T n + T²/2) · dhead

For agent actions, T is often tiny (a click JSON, a short plan line) while n is huge (screenshots + history). Then prefill dominates unless you incremental-cache. For long chain-of-thought dumps, decode catches up.

4. Memory: the KV cache formula

Per sequence (batch=1), storing keys and values:

KV_bytes ≈ 2 × L × Hkv × dhead × n × bytes_per_elem

For classical multi-head attention (MHA), Hkv = Hq and often Hq · dhead = dmodel, so

KV_bytes ≈ 2 × L × dmodel × n × bytes_per_elem

Worked example. L=32, dmodel=4096, fp16 (2 bytes), MHA:

bytes/token = 2 × 32 × 4096 × 2 = 524,288 ≈ 0.5 MiB/token
n = 8,192 → KV ≈ 4 GiB   |   n = 32,768 → KV ≈ 16 GiB

Switch to GQA with Hkv = Hq/8 (same dhead): multiply by 1/8 → ~0.5 GiB at 8k, ~2 GiB at 32k. MQA (Hkv=1) is the extreme (Shazeer, 2019); GQA interpolates (Ainslie et al., 2023).

Why MQA shrinks memory more than prefill FLOPs. Cache capacity and decode bandwidth scale with Hkv. Prefill FLOPs for an N-parameter model are still ~2N per token from dense projections; attention is often a minority of FLOPs for wide FFNs (Pope et al.). So MQA/GQA are primarily decode / memory optimizations — exactly where interactive agents live between short tool calls.

5. Multimodal token blowup

Text history is cheap compared to screenshots. Two public mental models:

  • ViT-style patches: a 1024×768 frame with 14×14 patches is on the order of (1024/14)×(768/14) ≈ 73×55 ≈ ~4k patch tokens before any merger/resampler. High-res tiling used by computer-use / UI agents can be in the same ballpark or higher.
  • API tile metering (GPT-4o / gpt-4.1 family, detail=high): scale so the short side is ≤768, cover with 512×512 tiles, cost ≈ 85 + 170 × (#tiles). A 1024×768 image → 2×2 tiles → 85+680=765 tokens (OpenAI vision docs). detail=low is a flat 85 — useless for precise grounding.

Agent arithmetic. Suppose each step adds one 765-token screenshot + 200 tokens of text/tools, and you keep raw history for H=30 steps with no compression:

n ≈ n0 + 30 × (765+200) ≈ n0 + 28,950

Every full re-prefill pays ~O(n²) attention. Summed over the trajectory without prefix reuse:

Σt=1H O(nt²) with nt≈t·S  ⇒  O(S² H³)

That is the systems twin of OSWorld's long-horizon pain: not only do errors compound (Oct 13) — compute compounds if the harness is naive.

6. Agent loops: cache reuse, truncation, summarization

Engineering synthesis for harness design.

  1. Static prefix caching. System prompt, tool schemas, and few-shot demos are identical across steps and often across sessions. Servers that hash and reuse KV for shared prefixes (vLLM PagedAttention can share blocks across requests) turn that into free memory and skipped prefill.
  2. Incremental append. After the first prefill, new observation tokens should extend the cache, not rebuild it. Continuous batching interleaves many sequences' decode steps while others prefill.
  3. Latest screen high-fidelity; old screens summarized. Grounding (Oct 11) needs pixels now. Older frames are usually better as a textual ledger ("opened Chrome; navigated to …; modal: Cookie consent dismissed") than as another 765–4k tokens each.
  4. Truncate with attention sinks / sliding windows when you must bound n: keep early "sink" tokens + recent window (streaming LLM literature). Risk: lose constraints stated mid-trajectory — pair with an explicit state ledger.
  5. Summarize vs truncate. Summarization is lossy compression with a model; truncation is hard deletion. For computer-use, summarize actions and state, truncate redundant pixels.
  6. When latent world models help (Oct 15). They cut K× future renders per decision. They do not remove the need for prefix cache + screenshot policy on the base observe→act context.

7. PagedAttention in one paragraph

Kwon, Li, Zhuang, et al. (SOSP 2023), "Efficient Memory Management for Large Language Model Serving with PagedAttention" — treat the KV cache like virtual memory: fixed-size blocks, non-contiguous physical storage, block table per sequence. That kills external fragmentation from over-reserving max length, and enables sharing identical prefix blocks across requests. For an agent farm where hundreds of sessions share the same system+tool prefix, that sharing is as important as the per-request math.

8. How this applies to computer-use agents

  • OSWorld-scale horizons (Oct 13): treat context management as part of the agent. A policy that never summarizes will hit context and latency walls before it hits capability walls.
  • Credit assignment (Oct 14): logging every frame helps offline RL and process rewards — but the online inferencing path should not replay that log as raw pixels every step.
  • Latent world models (Oct 15): reduce speculative perception cost; still combine with KV reuse so the base loop stays cheap.
  • Grounding (Oct 11): budget tokens for the current screenshot at high fidelity; spend remaining budget on structured history, not a museum of old bitmaps.
  • Measurement habit: for each harness change, log n, prefill ms, decode ms/token, KV GiB. If prefill ≫ decode on 40-token actions, you have a caching/history problem, not a "model is slow" problem.

9. Common misconceptions

  • "Attention is always O(n²) per generated token." Only if you refuse to cache K,V or you rebuild the full QK⊤ every time. Decode with cache is O(n) per step.
  • "KV cache is an implementation detail; FLOPs are all that matter." Decode is often bandwidth-bound; cache size caps batch and context (Pope et al.).
  • "MQA makes prefill dramatically cheaper." Memory yes; prefill FLOPs barely — FFN still dominates for large N.
  • "More screenshot history always helps the agent." It helps until n explodes; then you lose real-time interactivity and may even confuse the model with stale UIs.
  • "FlashAttention / speculative decoding fix agent latency end-to-end." They help specific phases. Agents need harness-level prefix reuse and multimodal history policy too.

10. One-paragraph summary

Causal LM inference splits into a parallel prefill that builds the KV cache at ~O(n²) attention cost and a sequential decode that attends with one new query against cached K,V at ~O(n) per step; computer-use agents amplify both sides because screenshots inflate n and every observation tempts a full re-prefill. KV memory scales as 2·L·Hkv·dhead·n·bytes, so GQA/MQA, quantization, and paged/prefix sharing are first-class agent infrastructure. Keep high-fidelity pixels for the live screen, compress older history, and measure prefill vs decode per step — that is how long-horizon GUI loops stay affordable without giving up grounding.
